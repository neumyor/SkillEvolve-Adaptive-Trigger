# 强→弱迁移中"经验载体"的设计分析：形式、动机与判断

分析日期：2026-10-09。对象：`docs/strong_to_weak_prompt_skill_survey_20261009.md` 短名单中
强模型经验传递给冻结弱模型的具体形式。问题：经验以什么形式传、为什么选这个形式、
设计上有什么讲究、我对每种形式的评价。证据以本地全文与 2026-10-08/09 两份调研的
F/L 级核对为基础；主观判断单独标出（**判断：**），不代表论文原文立场。

## 总览：七种载体形式

| # | 载体形式 | 代表工作 | 经验的抽象层级 |
|---|---|---|---|
| A | 结构化纠错文本（note/rule） | AgentBrew、Concept Distillation | 中：动作级规则 |
| B | 对比式技能补丁 | SKILL-KD | 中：失败-成功差异 |
| C | 分层记忆（按粒度分仓） | AMD | 高+中+低三层 |
| D | 可执行技能（代码/API/工具） | SkillWeaver、AgentDistill、SPARK | 低：确定性程序 |
| E | 教师 demo 检索（ICL 示例） | Inference-Time Distillation | 最低：实例级 |
| F | 去偏共享记忆 | MemCollab | 中：模型无关知识 |
| G | 整套 harness/路由系统 | AI4AI、AHE | 混合：系统级 |

## A. 结构化纠错文本：教师针对学生失败写"操作级"笔记

**代表**：AgentBrew（[2607.16851](https://arxiv.org/abs/2607.16851)）、Concept Distillation（[2408.09365](https://arxiv.org/abs/2408.09365)）、MNL（无教师版）。

**动机**：环境只有二值 reward，学生失败轨迹是唯一额外信号；教师自己会做的推理对学生
"读得懂、做不到"——AgentBrew 原文指出教师省略它认为显然的步骤、用词超出学生舒适区、
纠正规则过粗无法翻译成动作。因此笔记必须**按执行者（而不是作者）的粒度写**。

**设计要点**（AgentBrew）：
- 六字段动作导向 schema：具体触发条件、操作顺序、能力缺口标注、检查项等——强制教师
  写"什么局面下做什么"，而不是"这个领域有什么道理"；
- **student-aware prompting**：生成时就要求面向 S 的阅读水平和操作粒度；
- **Ralph Loop 准入**：笔记由学生在同一任务上重跑，环境通过才入库——把"教师觉得有理"
  变成"学生用得动"，拒绝对教师合理但对学生不可执行的指导；
- **skill-scoped 记忆分区**：按能力/环境切片划分互斥 scope，检索只在子集内排序，
  避免跨域笔记串扰；scope 路由用任务中的显式工具名/相似度/动作信号三梯队判定；
- serve 时只读冻结记忆，单次 rollout，无反思循环——保证测试时成本与教师退出。

Concept Distillation 是该形式的早期简化版：归纳规则 + 验证集筛选，无学生参与验证。

**判断**：这是最贴近"教学"语义的形式，核心创新不在文本本身而在**准入控制**
（学生执行 + 环境裁决）。它承认了一个多数工作回避的事实：教师知识对弱学生
默认不可用，必须"写给特定执行者"。弱点：(1) 文本笔记仍要求学生把语言翻译成动作，
收益上限受学生指令跟随能力约束；(2) AgentBrew 自己的 TB2.0 证据是温和的
（45.3→51.6，且弱于逐题配对审计所需的强度）；(3) scope 路由本身是新的失败点。
长期看，"笔记写多细"没有理论答案，只有 Ralph 这类事后裁决能兜底。

## B. 对比式技能补丁：把"差在哪"本身当作教学内容

**代表**：SKILL-KD（[2607.28048](https://arxiv.org/abs/2607.28048)）。

**动机**：单看学生失败或教师成功都不够——可教的东西恰恰在**两者的差**里；且教师不是
oracle，教师失败轨迹也含有效局部经验。

**设计要点**：
- 学生失败轨迹 + 同任务教师轨迹 → 文本"技能补丁"，明确表达差异；
- 学生重跑裁决：接受/合并/丢弃；失败时由 consolidation agent 根据"为什么失败"修订；
- **trace-linked 编辑历史**：每个补丁链接到源轨迹，控制重复、局部过拟合与技能漂移
  （Drift-Aware Skill Consolidation）；
- 教师/学生组合跨域验证（4B 学生五域宏平均 43.5→66.8）。

**判断**：对比信号是对的——它把"教学"定义为填补已知差值而非单向输出，这在概念上比
AgentBrew 的"教师读失败写笔记"更完整（AgentBrew 教师不看自己成功轨迹，SKILL-KD 双向看）。
它的独特贡献其实是**库治理**（edit log、漂移控制）：长期运行的记忆库死于此处而非检索。
弱点：技能作为整体文件喂给学生的设置较粗，没有 AgentBrew 那样的检索粒度；
每 benchmark 独立建库也削弱"终身"主张。

## C. 分层记忆：按粒度分仓、按时机注入

**代表**：AMD（[2608.07169](https://arxiv.org/abs/2608.07169)）。

**动机**：扁平教师记忆直接注入收益不稳（论文 Figure 1 的出发点）；不同失败需要不同
粒度的支持——任务级缺策略、子任务级缺操作、工具级缺 API 细节。

**设计要点**：
- Workflow 记忆（任务级策略）+ Subtask 记忆（具体子任务步骤）+ Function 记忆
  （工具调用与错误恢复）三层；
- **注入时机与粒度绑定**：Workflow/Subtask 任务开始时主动注入，Function 在工具报错时
  反应式检索；
- 教师从自己的成功轨迹生成记忆，学生（Qwen3-4B/8B 等）只读。

**判断**：这是对"经验该写多细"给出最直接实证答案的工作——**中间粒度（Subtask 示例）
贡献最大**，这符合直觉：策略太抽象、API 太局部，子任务示例恰好在弱学生"照着做"
的分辨率上。粒度×注入时机二维设计是可迁移的设计模板。弱点：教师不分析学生失败
（经验源是教师自我成功，与 A/B 相比少了 gap 信号）；严格 cross-split 增益（16→41 等）
虽显著但环境封闭（AppWorld/BFCL），开放 shell 未验证。

## D. 可执行技能：把确定性外包给代码

**代表**：SkillWeaver（[2504.07079](https://arxiv.org/abs/2504.07079)）、AgentDistill（[2506.14728](https://arxiv.org/abs/2506.14728)）、SPARK（[2605.09192](https://arxiv.org/abs/2605.09192)）。

**动机**：弱模型最大的不可靠在于**执行长过程**——一步错全盘输。把过程封装成确定性
程序/API，学生只需"知道何时调用"，把能力边界整体外包。

**设计要点**：
- SkillWeaver：教师探索网站→练习→合成/调试 Python/Playwright API，技能带前置条件、
  docstring、使用历史，入库前经过真实执行验证；同一批 API 直接给 GPT-4o-mini 用；
- AgentDistill：教师自主生成自包含 MCP-Box（工具+说明打包），学生 agent 直接集成；
- SPARK：**技能必须在 Docker 真实交互后形成**；提出 PDI（Posterior Distillation Index）
  量化技能内容中"环境证据"与"未验证计划"的比例，在线诊断并干预。

**判断**：这是**证据最硬**的形式——代码要么跑通要么跑不通，验证天然二值、无歧义；
SkillsBench 的 +16.6pp 主要也是这种"curated 可执行技能"的收益。但它转移的是**程序
而非判断力**：学生学到"何时用哪把锤子"，学不到"为什么这里该敲"。两个附带问题：
(1) 工具面扩大后归因混淆——学生变强还是工具变强？SkillWeaver 论文自己承认这种
封装本身就是合法机制，但引用它作为"弱模型能力提升"时必须分开算；
(2) SPARK 的 PDI 是全场最诚实的质量指标，直指行业痛点（见 138K 审计：91.8% 技能
含缺陷）。SKILL.md 把"说明+脚本"混合打包是务实赢家，因为把 A 的可读性与 D 的
可验证性合在一个工件里。

## E. 教师 demo 检索：最轻的"教学"，最重的工程

**代表**：Inference-Time Distillation（[2512.02543](https://arxiv.org/abs/2512.02543)，Stanford）。

**动机**：不是"如何教得最好"而是"如何又快又省"——prompt 工程脆、fine-tune 慢，
两者都损害部署敏捷性（agility）；教师只需要在小子集上出 demo。

**设计要点**：
- 教师跑小子集 → demo 库 → 学生在剩余任务上**逐步检索相关教师 demo 作 ICL**；
- 自一致性级联：学生多次采样一致则继续，分歧时升级到更强模型/教师；
- 无任何离线蒸馏管线，教师即用即走。

**判断**：最不像"蒸馏"的一档——它其实是用检索把教师的逐任务轨迹借给学生对比例照抄。
优点是系统极简、成本模型清晰、今天就能上线。弱点也来自同一处：实例级示例不抽象，
泛化依赖任务相似度，对未见任务族基本无效；且分歧升级意味着**教师并未真正退出**
（级联中教师仍在岗）。把它列为 strong→weak 迁移有点勉强，更像"强模型缓存复用"。

## F. 去偏共享记忆：正面处理"知识是模型特异的"

**代表**：MemCollab（[2603.23234](https://arxiv.org/abs/2603.23234)）。

**动机**：AgentBrew Figure 1 证明笔记必须按学生定制（现象），MemCollab 给出机制解释：
记忆把任务知识和**模型特异的推理风格/偏差**纠缠在一起，直接跨模型搬运会劣化。

**设计要点**：
- 让不同 backbone 在同任务上各自出轨迹，**对比蒸馏**出模型无关的共享记忆；
- 共享一套记忆服务异构（不同大小/架构/特化）agent。

**判断**：这是与 AgentBrew 最互补的一篇——AgentBrew 走"为每个学生定制"
（model-specific），MemCollab 走"蒸馏出 model-agnostic 共享层"。两条路线的张力
本质是：**知识里到底有多少是模型无关的？** 这是个没被回答的实证问题，也意味着
"通用技能库"是否可行悬而未决。方向很早（7 引用），但问的问题是对的。

## G. 整套 harness：不是教学生，而是换系统

**代表**：AI4AI（[2608.12307](https://arxiv.org/abs/2608.12307)）、AHE。

**动机**：有些能力根本无法通过 prompt 灌进弱模型；承认这一点后，把教学对象从
模型改为系统——强模型在小开发集上合成路由、prompt、确定性求解程序和输出检查。

**设计要点**：强 builder 离线搜索整个执行框架，冻结弱 target 直接住进去；四类组件
（路由/提示/程序/校验）同时演化。

**判断**：效果通常最猛，科学归因最差——所有东西同时动，无法回答"是哪部分在教学生"。
而且已有对照反证（Rethinking Harness Evolution：匹配预算下不优于简单 test-time
scaling）。它挑战了本调研的边界：如果"传递形式"是整个系统，那"弱模型学到什么"
这个问题本身就不成立了。作为 baseline 和上限参考有价值，作为科学研究对象太浑。

## 横向设计考量（跨形式比较）

1. **写给谁**：AgentBrew/SKILL-KD 把学生信息写进生成过程（student-aware prompting、
   学生重跑裁决）；AMD/Concept Distillation 用教师自己的语言写、学生被动读。
   前者的 Figure 1 类证据（笔记价值依赖 brewing 时的学生身份）正在变成共识。
2. **谁裁决、何时裁决**：Ralph（学生执行+环境 reward，事后）、SKILL-KD（学生执行，
   事后）、Concept Distillation（验证集筛选规则，不涉及执行）、SPARK PDI（证据性
   度量，事前+在线）、VaG（预提交门控）。**裁决严格度与形式的可验证性成正比**：
   代码易裁决所以 D 类验证最硬；文本难裁决所以 A 类必须靠学生重跑兜底。
3. **注入时机**：AMD 的 proactive（任务开始）/reactive（工具报错）二分是最清晰的
   模板；AgentBrew 的 scope 分区检索是另一种结构化时机控制。
4. **抽象层级谱系**：教师 demo（E，实例）< 纠错笔记（A，动作规则）< 子任务示例（C）
   < 领域规则（Concept Distillation）< 代码程序（D）。**越往左越保真越不泛化，
   越往右越抽象越需要验证**。没有工作证明某个层级普适最优；AMD 的证据偏向中间。

## 我的主观总结

1. **领域的重心正在从"写什么"转向"凭什么入库"**：Ralph、PDI、预提交门控、edit log、
   138K 审计全部是质量控制机制。这是成熟信号——大家已经默认"生成内容容易，可靠内容难"。
2. **文本与代码是基本权衡**：文本传判断力但不可验证，代码可验证但只传过程。
   SKILL.md 混合工件（说明+脚本）+ 学生执行准入是当前最合理的折中。
3. **"知识是模型特异的"是本方向最重要的实证发现**（AgentBrew Fig.1 + MemCollab
   的纠缠分析），它否定了"建一个通用技能库给所有模型用"的天真路线，但 model-agnostic
   成分到底有多少仍是开放问题——这可能是比"再造一个 brewing 流水线"更值得做的题。
4. 若按"对真弱学生的严格证据"排可信度：**D（可执行技能）> B（对比补丁）≈ C（分层
   记忆）> A（纠错笔记）> E（demo 检索）> G（harness）**；按"传递判断力而非过程"
   排则大致相反。两类主张在写作时必须分清，目前不少论文混着说。
