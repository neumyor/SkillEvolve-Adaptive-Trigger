## Objective and Scope

The predictor estimates `P(pass | dataset, target LLM, complete skill text, task text)`. It emits the two-class `noul` distribution `[P(fail), P(pass)]`. Conflicting pass/fail observations for an identical input are expected evidence about a probability and must remain represented in the target distribution.

The curated source currently contains 17,572 six-tuples across SearchQA (16,543) and ALFWorld (1,029), plus 46 Markdown skill artifacts. Reconfirm these counts from the source files during ingestion. The local source files are `data/skill_task_results_20260929/skill_task_result_six_tuples.jsonl`, `data/skill_task_results_20260929/skill_files/manifest.json`, and the task/run artifacts under `repos/` and `benchmark/`.

The experiment is one jointly trained model. The dataset marker is an input feature and final metrics are reported both per dataset and overall. The evolve method, result label, task/run ID, skill filename, source path, and gold answer are provenance only and are never model input.

## Fixed Protocol

### Input and labels

1. Resolve each tuple to its complete Markdown skill body and the actual task text used by the evaluated agent. Validate the skill body against its manifest SHA-256. Resolve task text with dataset- and source-run-aware mappings; task IDs are not task text. ExpeToSkill route lookup must use the exact task ID present in the matching route manifest; never infer an offset from the minimum route key.
2. A missing or ambiguous skill/task mapping is an ingestion error. Do not silently drop it, guess from a method name, or choose one candidate. Preserve a row-level resolution record with tuple row, source artifact, resolver, and canonical task group. Inspect representative resolved task inputs from every source family and trace the extractor to ensure it includes only the evaluated agent's user-facing task/state, not a gold answer, expected trajectory, score, or post-run observation.
3. Serialize the input state exactly as:

   ```text
   Dataset: {dataset}
   Target agent model: {llm}

   Skill:
   {complete skill Markdown body}

   Task:
   {complete task text}
   ```

4. Use one fixed question for all samples: type `noul`, instruction `Will one run of the target agent complete this task successfully when using the provided skill?`, options `false`, `true`. The answer order is `[false, true]`.
5. Aggregate only identical serialized states. Preserve `n_pass`, `n_fail`, `n_trials`, all source/method provenance, and set `target_probs = [n_fail / n_trials, n_pass / n_trials]`. Never collapse this target to a hard label for training. Audit exact duplicate source rows separately. Do not deduplicate merely because six tuple fields match: remove an observation only when row-level provenance proves the same underlying evaluation was imported twice; preserve genuine repeated runs and retain the duplicate audit trail.
6. Optimize the trial-level soft-label cross-entropy: for each unique input use `n_trials * (-q_fail log(p_fail) - q_pass log(p_pass))`; normalize by the total trial weight in the batch/metric. This corresponds to the observed Bernoulli trials while retaining one serialized input per example. Do not let provenance enter the features.

### Task grouping and split

1. Define a task group from the canonical benchmark task identity where available; otherwise use the SHA-256 of the dataset plus whitespace-collapsed, lowercased task text. SearchQA groups by the question/request, and ALFWorld groups by the requested goal, not by skill, method, model, or source-local task ID.
2. Split task groups independently within each dataset using deterministic ordering by `SHA-256("20260929|{dataset}|{task_group}")`. Assign the first `max(1, Python round(0.10 * n_groups))` groups to test, the next `max(1, Python round(0.10 * n_groups))` to validation, and the remainder to train. If fewer than three groups remain, stop and amend before training. This is a fixed group split, not a row split or label-stratified split.
3. Every skill, evolve method, target model, and repeated observation for one task group must stay in the same split. Assert pairwise disjoint task-group sets. Record per-dataset counts for groups, examples, trials, pass/fail mass, fractional-target examples/coverage (`0 < q_pass < 1`), and repeated-trial coverage in each split. If a split cannot support the declared metrics, stop and amend the protocol before training.
4. Freeze and checksum the split manifests before training. Validation may select a checkpoint; test remains unopened until model and all choices are frozen.

### Tokenization and input-length policy

Use the tokenizer from the remote `base/` model and the exact `encode_record` implementation in the remote Jev service code. **Protocol amendment 2026-09-29:** use state 6,144 tokens, causal row (`state + question branch`) 6,144 tokens, and packed record 6,400 tokens for this experiment. The original Jev `max_branch` argument limits the complete causal row, not only the question suffix. The first full audit under the original serving caps found 5,645/17,572 trials (32.1%) overflowed, disproportionately in SearchQA; all overflow reasons were state length. The base model supports 131,072 positions, the maximum observed untrimmed state was 5,684 tokens, and the fixed question/options add a short branch. These caps preserve the complete feature contract and cover the observed maximum with headroom. Training, validation, test, baseline inference, and the eventual fine-tuned service must use and record these same caps. The first audit and the intermediate 6,144/3,072 smoke are rejected candidates, not model-selection evidence. Audit both untrimmed and encoded lengths, the longest examples, and all overflow/truncation flags again under the amended caps.

The feature contract requires complete skill and task text. Therefore, do not silently accept Jev's default state trimming. Use strict encoding for the audit. Any sample that cannot fit all three amended limits is marked overflow and excluded as a complete input before the split is frozen; record its tuple rows, task group, lengths, and reason. Report exclusions per dataset and verify remaining task groups still satisfy split/metric requirements. If exclusions are material or disproportionately affect one dataset, stop for protocol review before training.

### Evaluation and reporting

Before full training, freeze these definitions:

- Primary: trial-weighted soft-label negative log-likelihood.
- Probability quality: binary Brier score is the trial-weighted mean of `(p_pass - q_pass)^2`. ECE uses 10 fixed equal-width bins `[0,.1), [.1,.2), ... [.9,1]`; within each bin, both mean prediction and soft pass target are weighted by `n_trials`, and ECE is the trial-weighted absolute gap between them.
- Thresholded diagnostics at `P(pass) >= 0.5`: expected balanced accuracy, fail recall, and expected macro-F1 from fractional confusion counts. For each input, add `n_trials*q_pass` to the true-pass mass and `n_trials*q_fail` to the true-fail mass, then allocate those masses to predicted pass/fail by the thresholded prediction. Compute the usual balanced accuracy and classwise F1 from this fractional confusion matrix; fail recall is `TN / (TN + FP)` when pass is the positive class.
- Report all metrics overall and separately for SearchQA and ALFWorld. Report the original Jev checkpoint on the same validation/test rows as the baseline; do not use that baseline to revise the protocol.
- For test confidence intervals, use 2,000 stratified bootstrap replicates, seed `20260929`: within each dataset, resample its test task groups with replacement, keeping the original number of groups and all examples/trials within each sampled group. Recompute per-dataset and overall metrics; overall metrics retain the observed test trial mix. Report 95% percentile intervals.
- After model selection and final checkpoint freeze, evaluate test exactly once and save one probability per unique input plus the counts/provenance needed to reconstruct trial-level metrics. Report split/exclusion sizes and the historical Jev SearchQA check as prior use, not as an independent holdout result.
